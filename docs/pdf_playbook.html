1 Executive Architecture & Core Security Guarantees

Sentinel AI is an enterprise application-layer security gateway mediating all interactions between authenticated client applications and Large Language Model (LLM) providers. It systematically eliminates the three primary channels of AI data leakage:

  • Input Leakage: Sensitive PII (emails, phone numbers, Indian Aadhaar & PAN cards) and credentials (AWS keys, API tokens) pasted into prompts.
  • Retrieval Leakage: Unauthorized document snippets fetched during RAG and injected into model context.
  • Output Leakage: Model repeating internal credentials or memorized sensitive data in generated answers.
User Prompt (Client) │ ▼ [1. Authentication] ───► Verify user identity & derive tenant / doc scopes │ ▼ [2. Input Inspection] ──► Presidio + Regex: Email, Phone, Indian Aadhaar/PAN, AWS/API Keys, Injections │ ▼ [3. Policy Engine] ────► Evaluate ALLOW / MASK / BLOCK │ │ │ └─► IF BLOCK ───────► 🛑 TERMINATE IMMEDIATELY (Upstream Provider is NEVER called) │ ▼ [4. Pre-Retrieval ACL] ─► Verify document permissions server-side BEFORE retrieval │ ▼ [5. LLM Adapter] ──────► Call OpenAI / Groq / Anthropic or Offline Mock with Server-side Key │ ▼ [6. Output Filter] ────► Inspect generated response; redact PII or block credential leaks │ ▼ [7. Privacy Audit] ────► Store structured metadata (ZERO raw prompt or response in DB) │ Sanitized User Response
The Cardinal Rule: Block-Before-Forward (FR-005)
If a prompt receives a BLOCK decision due to credentials, API keys, or prompt injections, the upstream LLM provider must never be invoked. Automated security tests must strictly assert that provider call count is zero.

3 Member 1 Deep Dive: Security Architect

Primary Objective: Intercept prompts, detect sensitive entities, apply policy precedence, and guarantee that blocked prompts never leave the server.

Owned Files & Structure:

  • backend/auth/models.py & backend/auth/jwt.py: JWT decoding and role claims (end_user, policy_admin).
  • backend/detection/pii_detector.py: Regex and Presidio detectors for Email, Phone, Indian Aadhaar (12 digits), Indian PAN (`[A-Z]{5}[0-9]{4}[A-Z]`), Credit Cards, and Hinglish markers.
  • backend/detection/secret_scanner.py: Regex patterns for AWS keys (`AKIA...`), OpenAI keys (`sk-...`), GitHub tokens, passwords.
  • backend/detection/injection_detector.py: Heuristic detector for prompt jailbreaks, overrides, and system prompt leaks.
  • backend/policy/engine.py: Precedence evaluation and right-to-left deterministic masking transformer.
  • backend/gateway/orchestrator.py: Central gateway orchestrator.
  • tests/unit/test_detection.py & tests/security/test_block_before_forward.py: Unit and security tests.

7 Git Branching Strategy & Collaboration Workflow

To avoid conflicts while all 3 members work concurrently:

  • main: Production-ready baseline. All tests must pass before merging.
  • feature/member1-gateway-detection: Owned by Member 1 (Auth, Detection, Policy, Orchestrator).
  • feature/member2-provider-acl: Owned by Member 2 (LLM Adapter, ACL, DocStore, Output Filter).
  • feature/member3-audit-ui-eval: Owned by Member 3 (Audit Logger, Benchmark Suite, Web UI, Docker).
Standard Pull Request (PR) Acceptance Checklist:
1. pytest tests/ -v passes with 0 failures.
2. Block-Before-Forward test confirms provider call count is 0 on blocked prompts.
3. Pre-retrieval ACL test confirms unauthorized documents are omitted.
4. Audit DB verification confirms 0 raw sensitive prompts exist in storage.
